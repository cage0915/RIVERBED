# Mountain profile and map plan

## 目標

在 `src/pages/tags/[tag].astro` 的照片列表上方加入山岳 profile：

- 左欄顯示高度、描述等文字資訊。
- 右欄顯示極簡底圖，並以山岳的經緯度標示位置。
- 山岳名稱放在左欄第一項，不在 profile 上方另外置中顯示。
- 每座山設定一個預設初始範圍；訪客使用滾輪縮放、拖曳平移，不使用範圍下拉選單。
- 第一階段先使用極簡行政輪廓，但架構需保留未來切換地形底圖的能力。
- 沒有任何山岳資料的 tag 頁必須維持目前版面，不顯示空 profile。

## 已確認的產品決策

1. 訪客以滾輪和拖曳自由探索同一份 master map，不提供北阿／長野／本州等範圍下拉選單。
2. 地圖範圍不限於國家／縣市，也支援跨行政區的自訂區域，例如日本北阿爾卑斯。
3. 台灣本島、日本本州等範圍可以透過行政區篩選與經緯度 bounds 裁切，不必顯示整個國家。
4. 第一階段只做極簡輪廓；地形圖延後，但底圖 layer 不可與山岳資料耦合。
5. 照片中出現 tag 即代表看過／拍過，不在 `mountains.json` 重複保存 `seen` 狀態。
6. 登頂狀態與總覽地圖不屬於第一階段。
7. 同一 coverage 的不同 Context 共用一份 master SVG；縮放與裁切由動態 `viewBox` 完成，不為每個 Context 重複產生 SVG。
8. marker 在渲染時與底圖放進同一個外層 `<svg>` 座標空間，但山岳永久資料仍只保存經緯度，不保存 SVG `x/y`。
9. 後續總覽地圖可切換「登頂過／只看過」，但這兩類應定義成互斥分類，避免同一座山同時屬於兩個開關而產生混淆。
10. Profile 不顯示 `MOUNTAIN` 與 `LOCATION` 裝飾字樣。
11. 山岳名稱移到左欄第一項並提高字級；高度字級縮小，讓資訊層級以山名為主。
12. Google Maps 延後到下一階段評估；目前的 SVG 地圖保留，不以 Google 實作取代或耦合山岳資料。
13. 未來可由後端／部署設定在 `svg` 與 `google` provider 之間切換，訪客不負責選擇 provider。
14. 山岳座標與初始視野繼續由本站資料維護，不保存到 Google 帳戶；Google 只負責底圖與互動渲染。
15. `mapContext` 用來選擇 SVG source 與初始 geographic bounds；未來應維持為 provider-neutral 的顯示情境 ID，不直接代表 SVG 檔案或 Google Map ID。
16. 位置圖與「從山頂眺望」共用右欄同一個 viewer 空間，由訪客切換「位置／視野」，不在頁面同時占用兩塊區域。
17. 視野圖第一版使用 PeakFinder iframe，預設不載入；訪客首次切到「視野」時才送出第三方請求。
18. PeakFinder 不作為山名、座標或高度的資料來源；它只消費本站已確認的 viewpoint 資料並渲染計算生成的 360° 地形視野。
19. PeakFinder 受伺服器端 `PEAKFINDER_ENABLED` feature flag 控制；關閉時不輸出視野頁籤、iframe URL 或第三方請求，但保留 mountain entry 的 panorama 設定。

## Phase 1 完成後的介面修正

- 移除訪客範圍下拉選單，改成直接以滑鼠滾輪縮放、拖曳平移。
- 每個 `mapContext` 直接提供初始 bounds；DevTool 可編輯共享的 Context 範圍。
- 滾輪縮放以游標位置為中心，marker 與底圖保持在同一個 SVG 座標空間。
- 移除 profile 上方置中的山岳名稱，改放在左欄第一項。
- 移除 `MOUNTAIN` 與 `LOCATION` 字樣。
- 山岳名稱字級調大為響應式 `1.75rem–2.5rem`；高度縮小為 `1.875rem–2.75rem`。
- 訪客顯示／隱藏「登頂過／只看過」不納入第一版，但資料與 renderer 不應阻礙後續加入。
- 大霸尖山與白馬岳加入 PeakFinder 測試設定；兩者可在同一 viewer 中切換位置圖與視野圖。

## 核心架構

將地圖拆成以下獨立概念：

```text
山岳經緯度
    ↓
Map Context：選擇 source、顯示範圍、行政區篩選
    ↓
Map Source：master asset、投影、座標範圍
    ↓
Map Layer：極簡輪廓；未來可加入地形、等高線等
```

重要原則：

- `mountains.json` 永遠保存原始經緯度，不保存針對特定圖片算出的 `x/y %`。
- marker 與底圖使用同一個投影函式。
- 投影後的 SVG `cx/cy` 只是當次渲染的暫時結果，不寫回山岳資料。
- Map Context 與 Map Layer 分離；更換地形底圖不需修改山岳資料。
- 第一階段統一使用 Web Mercator，方便日後對接常見地形圖或圖磚。
- 地圖來源、授權與 attribution 記錄在 source/layer 設定，不分散到頁面中。
- Map Source 提供完整 coverage 的 master SVG；Map Context 提供 SSR 初始 geographic bounds，訪客操作後由前端動態更新 `viewBox`。
- `MountainProfile` 只傳遞 provider-neutral props：經緯度、`mapContext` 與山名，不直接依賴 Google 或 SVG 專用欄位。
- provider 的選擇屬於網站／後端設定，不屬於單一 mountain entry。

## 資料結構

### mountains.json

第一階段沿用 `name` 查找，新增可選的 `location`：

```json
{
  "name": "白馬岳",
  "elevation": 2932,
  "description": "",
  "location": {
    "latitude": 36.7585,
    "longitude": 137.7586,
    "mapContext": "jp-northern-alps",
    "initialBounds": {
      "west": 137.2,
      "south": 36.4,
      "east": 138.1,
      "north": 37.1
    }
  },
  "panorama": {
    "provider": "peakfinder",
    "azimuth": 180,
    "altitude": 0,
    "fieldOfView": 45
  },
  "dataSource": {
    "wikidataId": "Q200126"
  }
}
```

欄位規則：

- `latitude`：-90 到 90。
- `longitude`：-180 到 180。
- `mapContext`：必須對應已定義的 context。
- 缺少 `location` 時仍可只顯示文字資訊。
- 第一階段不加入 `seen`。
- 第一階段不處理 UUID migration；未來支援同名山時，必須同時讓照片 tag 保存 mountain ID，只有在 `mountains.json` 加 UUID 並不能解決歧義。
- 沒有 `initialBounds` 時使用 `mapContext` 的 bounds。
- `panorama` 是選填欄位；只有設定 provider 的山才顯示「視野」頁籤。
- `azimuth`、`altitude`、`fieldOfView` 都是選填的初始視角；未設定時使用 PeakFinder 預設值，可由 DevTool 編輯。
- PeakFinder URL 每次由山岳既有經緯度、高度與 panorama 設定產生，不在資料中重複保存完整 iframe URL。
- `dataSource` 只記錄自動查詢採用的 Wikidata QID，作為資料來源連結；查詢時間不影響顯示或更新流程，因此不保存 `retrievedAt`。自動填入後仍必須由編輯者確認。

### Map Context

Context 就是一個可由山岳共用的完整地圖情境，直接包含 source、初始範圍與行政區篩選：

```json
{
  "id": "jp-northern-alps",
  "label": "日本北阿爾卑斯",
  "level": "region",
  "source": "japan",
  "bounds": {
    "west": 136.95,
    "south": 35.7,
    "east": 138.4,
    "north": 37.25
  },
  "visibleFeatures": ["JP-15", "JP-16", "JP-20", "JP-21"]
}
```

可編輯的 contexts 位於 `src/map-contexts.json`；Map Sources、投影、驗證與互動函式仍保留在 `src/lib/mountain-map.ts`。DevTool 的 Context 編輯與另存功能只寫 JSON，不直接改寫 TypeScript。

山岳只保存 context ID；visitor map 直接讀該 Context 的 `source` 與 `bounds`。

目前 `mapContext` 仍是必要欄位，負責從 `MAP_CONTEXTS` 找到 SVG master source 與初始範圍。未來加入 Google provider 後，context ID 保持不變，但其設定可按 provider 分開：

```ts
{
  id: "tw-dabajian",
  providers: {
    svg: {
      source: "taiwan",
      bounds: { west: 120.8, south: 24.2, east: 121.5, north: 24.8 }
    },
    google: {
      initialBounds: {
        west: 120.8,
        south: 24.2,
        east: 121.5,
        north: 24.8
      },
      defaultMapType: "terrain"
    }
  }
}
```

這是下一階段的目標結構，不在第一階段先行改寫。Google 的 `center/zoom` 可在 runtime 由 geographic bounds 與容器尺寸算出，避免把初始視野綁死在 Google zoom 或 SVG `viewBox`。

Context 的 `bounds` 會在 SSR 時投影成 master SVG 的初始 `viewBox`。互動地圖載入該 Map Source 的所有 features，讓訪客能拖曳到初始範圍以外；`visibleFeatures` 保留給未來靜態圖或總覽圖使用：

- 日本本州：只保留本州都府縣，排除北海道、四國、九州及沖繩。
- 長野縣：只保留長野縣 polygon，bounds 貼合縣域。
- 北阿爾卑斯：保留長野、富山、岐阜、新潟等周邊 polygon，再以 bounds 裁切到山域。
- 台灣本島：排除不需要的離島，再以 bounds 保留本島及指定近海島嶼。

不同初始範圍不需要建立額外 SVG 檔案。

### Map Source

Map Source 描述 master SVG、投影和來源資訊：

```ts
type MapSource = {
  id: string;
  asset: string;
  projection: "web-mercator";
  extent: [x: number, y: number, width: number, height: number];
  attribution?: {
    label: string;
    url: string;
  };
};
```

第一階段至少有台灣與日本兩個 outline sources。Map Context 引用 source；Mountain 不直接引用 SVG asset。

## 地圖資產策略

1. 使用 WGS84 GeoJSON 作為原始輪廓資料。
2. 以我們控制的 Web Mercator 轉換，為每個 coverage/layer 產生一份精簡 master SVG，而不是每個 Map Context 一份。
3. master SVG 中的行政區 paths 需保留穩定 feature ID，供 `visibleFeatures` 選擇。
4. 原始大型 GeoJSON 不送到訪客瀏覽器，也不在每個 tag request 重複處理。
5. Map Context 的 geographic bounds 會投影成動態 SVG `viewBox`，因此新增山域通常只需新增 Context。
6. 底圖 paths 與 marker 在渲染時放進同一個外層 `<svg>`，共同接受 `viewBox` 的裁切與縮放。
7. marker 的 SVG `cx/cy` 每次都從原始經緯度計算，不保存成資料，也不嵌入 master SVG asset。
8. marker 半徑需依目前 viewBox 計算，使全國與區域視圖中的視覺大小大致一致。
9. master SVG 應以可快取的形式載入；prototype 可先 inline，確認後再決定使用外部 `<use>`、SVG fragment 或載入後注入。
10. 所有資產需保留來源與授權資訊。
11. 滾輪縮放以游標所在的 SVG 座標為中心；拖曳平移與縮放都限制在 Map Source extent 附近，避免迷失在無限空白中。

預計資產形式：

```text
public/maps/
├── taiwan-outline.svg
└── japan-outline.svg
```

台灣本島、縣市、日本本州、長野與北阿等範圍由 Context metadata 表達，不各自建立檔案。實際檔名與 SVG 引用方式在 prototype 時確認。

## 元件與責任

### MountainProfile.astro

- 接收 mountain entry。
- 在左欄使用 `<h1>` 顯示山岳名稱，接著才是高度與描述。
- 不顯示 `MOUNTAIN` 裝飾文字。
- 決定文字欄與地圖欄是否存在。
- 桌面雙欄，手機改為上下排列。
- 只有單欄有資料時使用完整寬度。
- elevation 顯示單位為公尺。

### MountainMap.astro

- 接收經緯度與 `mapContext`。
- SSR 顯示 Context 初始範圍，沒有 JavaScript 也看得到初始地圖。
- 不顯示範圍 selector 與 `LOCATION` 裝飾文字。
- 滾輪以指標位置為中心縮放；pointer drag 平移地圖。
- 鍵盤方向鍵可平移，`+`／`-` 可縮放，`Home`／`0` 與雙擊可重設初始範圍。
- 依 Map Source extent 限制最遠平移及縮放上下限。
- 使用 Map Source 的投影重新計算 marker，並與底圖 paths 一起畫在同一個外層 `<svg>`。
- master SVG 不包含山岳座標；`circle` 或 marker `<g>` 由頁面渲染器產生。
- 經緯度落在 view 外時不顯示錯誤 marker，並提供可診斷的 fallback。
- 預留 `layer="outline"` 介面；第一階段不顯示 layer 切換 UI。
- attribution 使用低干擾但可辨識的方式呈現。

目前 `MountainMap.astro` 是 SVG renderer。加入第二個 provider 時，將它調整為共用入口，再委派給 `SvgMountainMap` 或 `GoogleMountainMap`；兩者接收相同的 mountain props。

```text
MountainProfile
      ↓
MountainMap（provider-neutral facade）
      ├── SvgMountainMap
      └── GoogleMountainMap
```

### MountainViewer.astro

- 作為右欄共用顯示空間，預設顯示既有 `MountainMap`。
- 有 `panorama.provider="peakfinder"` 時顯示「位置／視野」頁籤。
- 首次切換到「視野」才把 URL 指派給 iframe，避免未觀看時載入 PeakFinder。
- iframe 與位置圖使用相同 `16:10` 顯示比例；PeakFinder 失效時不影響位置圖與文字 profile。
- 頁籤支援滑鼠及鍵盤方向鍵、Home／End 操作。
- 只有伺服器端 feature flag 開啟且 mountain entry 設有 PeakFinder provider 時，才建立視野頁籤及 embed URL。

PeakFinder feature flag：

```text
PEAKFINDER_ENABLED=true   # 開啟；未設定時亦維持開啟
PEAKFINDER_ENABLED=false  # 關閉
```

`false`、`0`、`no`、`off` 均視為關閉；Cloudflare 使用 runtime environment binding，本機可使用環境變數。這是整站開關，不改寫 `mountains.json`，因此重新開啟後原有兩座測試山會恢復視野功能。

### Map 設定與投影 utility

- `src/map-contexts.json` 集中保存可由 DevTool 編輯的 contexts；每個 Context 直接包含 source、bounds、level 與 `visibleFeatures`，TypeScript 集中保存 sources 與 assets metadata。
- 提供 Web Mercator 經緯度轉 SVG 座標的純函式。
- 提供 SVG viewBox 與 geographic bounds 的雙向轉換，讓編輯器保存 provider-neutral viewport。
- 驗證 context、bounds 及座標。
- 投影函式應可單獨測試，不依賴 DOM。

### tags/[tag].astro

- 以 `decodedTag` 查找 `mountains.json`。
- 找到 mountain 且至少有文字或位置資料時，才插入 `MountainProfile`。
- 下方既有照片分組與空狀態不變。

## 訪客地圖互動

- 預設顯示 Context 定義的區域範圍，例如白馬岳先顯示北阿爾卑斯。
- 游標停在地圖上時，滾輪以游標位置為中心縮放。
- 按住並拖曳可平移，地圖使用 grab/grabbing cursor 回饋狀態。
- 同一 Map Source 的所有行政區共用已載入的 master SVG；互動只更新外層 `viewBox`。
- marker 與底圖在同一 SVG 座標空間，因此縮放和平移時自然保持對齊。
- 每次載入頁面都從該山 Context 的 bounds 開始，不跨山岳保存訪客操作狀態。
- 地圖可取得 keyboard focus，並提供螢幕閱讀器操作說明。

## 分階段執行

### Phase 0：資料與視覺 prototype

1. 選定大霸尖山與白馬岳作為測試山岳。
2. 手動加入兩座山的高度、描述、座標與 map context。

6. 確認深色頁面的底圖線條、marker、留白與兩欄比例。

Prototype 實作採用 geoBoundaries 的台灣／日本 ADM1 WGS84 邊界，底層資料來自 OpenStreetMap 並依 ODbL 1.0 標示來源。若未來改回 Simplemaps 或其他來源，只替換 Map Source 與 master SVG，不修改山岳經緯度或 Map Context 的概念。

1. 定義 Mountain、MapContext 型別與資料驗證。

3. 建立 Web Mercator 投影 utility 及測試。

9. 執行型別檢查、build 與瀏覽器驗證。

### Phase 2：開發工具與資料維護

1. 在 dev 模式提供 mountain entry 編輯 UI。
2. 編輯 elevation、description、latitude、longitude 與 map context。
3. 編輯者直接在預覽地圖使用滾輪與拖曳調整初始 viewport。
4. 將目前 SVG viewBox 反算／轉存為 geographic bounds，作為該山的 viewport override；不保存 marker 圖片百分比。
5. 提供既有 Context 的 ID、名稱與 bounds 編輯，以及另存新 Context 的操作。
6. 提供 PeakFinder iframe 視野預覽，以數值調整並保存 `azimuth`、`altitude` 與 `fieldOfView`，不保存完整 iframe URL；跨網域 iframe 內的拖曳方向無法自動讀回。
7. 提供啟用／停用 PeakFinder 視野的選項；找不到合適視角時仍可只保留位置圖。
8. 驗證並安全寫回 `mountains.json`。

Phase 2 第一版已完成：

- `MountainDevTool.astro` 以獨立 dev-only dialog 整合到全站 Layout，不修改既有照片 Tag／Page Manager 流程。
- 可選擇既有山岳，編輯高度、描述、經緯度、Map Context 與 PeakFinder 設定；暫不支援改名，避免破壞照片 tags 與 URL。
- Mountain 使用可操作的自製下拉清單；同時具備高度、有效經緯度與有效 Map Context 的山岳，在選項右側顯示綠色勾勾，方便辨識資料完整的項目。
- 切換 Mountain 時同步導向 `/tags/{山名}` 對應頁面；頁面載入後自動重新開啟 Mountain Manager 並載入所選山岳。
- 「自動查詢」透過本站 dev-only API 呼叫 Wikidata，合併中文、日文與英文搜尋候選，讀取 `P625` 座標及 `P2044` 高度。
- 搜尋結果會排除同時缺少高度與座標的候選；套用候選後立即收起結果，若要改選可再次搜尋。
- 查詢結果不直接自動保存；編輯者選擇候選後仍可覆寫所有欄位，查不到時完全手動輸入。
- 套用具有座標的候選時，依包含該點且範圍最小的 bounds 建議 Map Context。
- Context 編輯區固定顯示；`完整台灣` 與 `完整日本` 是 `protected` code-owned contexts，只有直接修改原始碼才能刪除。Context 使用可操作的自製下拉清單：完整底圖選項旁顯示新增 icon，新的範圍以該底圖為來源；其他 Context 選項旁顯示刪除 icon。
- 刪除 Context 前顯示引用山數與確認視窗；即使仍有引用也允許刪除，但保留山岳座標及失效的 `mapContext` ID。DevTool 與 production 遇到不存在的 Context 時都不顯示 Location map，直到編輯者重新指定有效 Context。
- Context 範圍儲存使用同行的 icon-only 按鈕，並以 tooltip／`aria-label` 區分 `Update Range` 與 `Save Range as New Context`。
- `Update Range` 寫檔前顯示確認視窗，說明會立即更新 context 並保存目前山岳草稿；若修改 Context ID，也會提示所有山岳引用將同步遷移。取消時不寫入。
- `Update Range`／`Save Range as New Context` 寫入 JSON 觸發 dev server HMR 時，DevTool 會以一次性的 session 狀態自動重新開啟，並還原當時的山岳與 Context，不中斷編輯流程。
- 位置預覽支援游標中心縮放與拖曳；座標欄位旁的 refresh icon 可在存檔前切換相容 Map Source、將 viewport 置中到新座標並預覽 marker。範圍直接保存到 Context 的 bounds，不再由這個介面建立山岳專屬 `initialBounds`。
- DevTool 的 Location 與 PeakFinder 共用一個 preview 空間，可用 tabs 手動切換；focus 進入 Basic Data／Map Context 時自動顯示 Location，focus 進入已啟用的 PeakFinder 設定時自動顯示 Panorama。Location bounds 以 `N / E / S / W` 單行摘要顯示。
- Context 不再建立內部 View ID；新增時直接從完整台灣／日本 Context 繼承 source 與 `visibleFeatures`，並保存目前 bounds。建立 Context 與目前山岳資料在同一 request 保存，避免 JSON HMR 造成未存欄位遺失。
- 修改既有 Context ID 時，後端同步遷移所有山岳的 `mapContext` 引用；名稱與 bounds 直接更新在 Context。
- Mountain DevTool 的可見標籤、按鈕、提示與狀態訊息統一使用英文，與既有 DevTool 保持一致。
- 所有山岳與 context 寫檔 API 僅在 `import.meta.env.DEV` 開放，production 回傳 403。
- PeakFinder 預覽使用 iframe；調整數值後按同行的 refresh icon 更新視野預覽，完整 URL 不寫入資料。

### Phase 3：地形與總覽地圖

1. 將 `MountainMap` 整理成 provider-neutral facade，保留既有 SVG renderer。
2. 由後端／部署設定選擇 `svg` 或 `google`，例如 `MOUNTAIN_MAP_PROVIDER=svg|google`；provider 不寫進個別 mountain entry。
3. 實作 Google Maps renderer，沿用本站保存的經緯度、`mapContext` 與 geographic bounds。
4. Google renderer 提供 `terrain`／`satellite` 底圖切換；Google `terrain` 是一般地形底圖，不視為專業登山等高線圖。
5. Google API key、billing、Map ID 與樣式設定放在 Google Cloud／部署環境，不放在 `mountains.json`；座標不需保存到 Google 帳戶。
6. 限制 API key 的 HTTP referrer、設定 quota／預算通知，並延遲到地圖進入可視範圍後才載入，以控制 Dynamic Maps 成本。
7. 若不採 Google，選擇具有合適授權的地形來源，以相同 Web Mercator 座標系建立 terrain Map Sources；既有 geographic bounds 可沿用。
8. 視 provider 能力加入「極簡／地形」或「地形／衛星」layer 切換。
9. 建立總覽地圖，使用目前啟用的 renderer 投影多座山的 markers。
10. 由現有照片 tags 推導 `seen`，不寫入 `mountains.json`；只有具有效座標的山能出現在地圖上。
11. 在 `mountains.json` 加入 `summited` 或 summit records，表示人工維護的登頂資料。
12. 將總覽 marker 分成互斥類別：
   - `summited`：登頂過，不論是否也有照片 tag。
   - `seen-only`：有照片 tag，但沒有登頂紀錄。
   - `unknown`：兩者皆無，預設不顯示。
13. 提供兩個獨立開關「登頂過」與「只看過」；顯示結果是目前啟用類別的聯集。
14. 使用不同 marker 樣式及圖例區分兩類，例如登頂為實心、只看過為空心。
15. 在需要支援同名山以前，規劃 mountain ID、URL 與既有照片 tag 的完整 migration。

### Google Maps 可行性與成本備註（2026-07）

- Maps JavaScript API 原生支援 `terrain`、`satellite`、滾輪縮放與拖曳。
- Dynamic Maps 以成功載入地圖計費；同一地圖實例內的平移、縮放與底圖切換不需要把座標保存到 Google，也不改變本站的 mountain schema。
- 全球標準 PAYG 目前每個月前 10,000 次 Dynamic Maps 載入免費，其後第一級為每 1,000 次 US$7；價格可能調整，實作時須重新查閱官方表格。
- Google Cloud 必須啟用 billing，即使用量落在免費額度內。
- 官方價格：https://developers.google.com/maps/billing-and-pricing/pricing
- SKU／計費事件：https://developers.google.com/maps/billing-and-pricing/sku-details

## 第一階段驗收條件

- 沒有 elevation、description、location 的 tag 頁與目前外觀一致。
- 只有文字資料時，文字區使用完整寬度。
- 只有位置資料時，地圖區使用完整寬度。
- 同時有資料時，桌面顯示雙欄，手機顯示上下排列。
- 山岳名稱是左欄第一項；頁面上方不再重複置中顯示。
- 不顯示 `MOUNTAIN`、`LOCATION` 或範圍下拉選單。
- 設定 PeakFinder 的測試山可在右欄同一空間切換「位置／視野」，未設定的山只顯示位置圖。
- PeakFinder iframe 只有在訪客首次切換到視野後才載入，切回位置圖不銷毀 iframe。
- Context 初始 bounds 在 SSR HTML 中可見。
- 訪客可使用滾輪縮放、拖曳平移及鍵盤操作，且不重新載入頁面。
- 縮放以游標位置為中心，拖曳方向符合直覺，並限制在 master source extent 附近。
- 每次互動後 marker 與底圖仍保持正確對齊，marker 視覺大小大致一致。
- 不把大型 GeoJSON 傳到訪客瀏覽器；同一 source 的 Contexts 共用一份 master SVG。
- 無效座標、缺少 context 或載入失敗時不破壞整個 tag 頁。
- attribution 正確呈現。
- Astro 型別檢查與 production build 通過。

## 第一階段明確不做

- 地形圖 layer 與 layer 切換 UI。
- 所有山岳的總覽地圖。
- 「登頂過／只看過」marker 篩選與圖例。
- `seen` 欄位。
- 登頂狀態 UI。
- UUID／同名山 migration。
- 圖磚、地名搜尋、路線、比例尺等完整 GIS 功能。
